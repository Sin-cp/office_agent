# 聊天中新建 Word 文档

发送“生成一份……Word 文档”即可创建独立 `.docx`，无需先上传空白文件。上传附件不意味着修改附件：只有明确要求修改才走修改流程；“参考附件另写一份”读取指定附件并创建新文件。目标含糊、关键年份缺失或一次要求新建多份时，系统先澄清。

新文档保存在当前项目中，项目文件列表用“上传 / 生成”区分来源。回复提供预览和下载，列表提供删除；生成后自动加入附件选择，保留原有选择。删除不会删除聊天记录，历史文件卡片会显示不可用。源文件已产生的修改结果仍保留。

首版每轮新建一份 Word，支持标题、三级章节标题、正文、项目列表、编号列表和简单矩形表格；默认 A4、中文字体和统一段落间距。不支持图片、复杂模板或其他输出格式。新文件使用独立存储 ID，同名不覆盖。

联网遵循输入框开关；新建文档需要实时资料时可自动查询，来源随回复保存。参考附件只在模型明确选择后读取，总参考内容最多 60,000 字符；生成内容最多 300 个区块、120,000 个 JSON 字符，每张表最多 100 行、10 列。文档超过 10 MiB 或校验失败时不发布。

任务结果新增 `kind: create`，复用 `file` / `outputs`。项目文件列表新增 `origin: uploaded | generated`，旧项目迁移为 `uploaded`。服务启动自动执行增量数据库迁移。模型生成结构化内容，后端负责 DOCX 渲染与校验；临时文件及数据库提交沿用现有发布与恢复机制。

验证：

```sh
cd backend
.venv/bin/python -m unittest discover -s tests -q
# 可选：使用当前配置调用付费模型，数据位于临时测试目录。
.venv/bin/python evaluate_creation.py --live
```

真实联调报告默认写入 `/tmp/office-agent-creation-evaluation.json`，覆盖无附件新建、有附件独立新建、参考附件新建、明确修改；测试不修改现有项目。

## 生成容错与诊断

新建文档结构校验失败时，保留原请求和资料，携带校验字段及上一次输出重新生成完整文档，最多纠正两次。网络连接、响应传输或超时允许重试一次，所有类型合计最多三次生成尝试，仍计入每轮 20 次模型调用预算；HTTP 参数错误不盲目重试。取消立即结束重试，只有完整校验通过的文件才保存。

任务 `creation_attempt` 表示当前生成尝试，`activity` 展示生成、纠正和重连过程；步骤更新为“生成文档内容 / 校验文档 / 保存结果”。失败调用指标新增 `error_category` 和安全的 `validation_errors`（字段路径与错误类型）；不会将模型正文、校验输入值或未知字段名称写入任务诊断。错误输出仅在当前纠正调用中使用。

可运行 `evaluate_creation.py --live --web --case 招聘报告`，在隔离项目中验证联网招聘报告生成、下载与预览。
