# DeepSeek 单段修改与任务生命周期

## 使用方式

上传 DOCX 或在文件管理中点击“修改文件”，输入明确的单段修改要求后发送。系统直接调用模型、校验修改并生成独立文件，不需要再次确认预览。原文件保留。结果可下载或查看；成功后自动选中新版本，下一次输入会继续修改该版本。

首版支持正文标题和普通段落。表格、页眉页脚、文本框及含图片、链接、域等复杂结构的段落不支持修改。段落边界的成对空书签（包括 `_GoBack`）可保留并编辑，拼写/语法检查标记不再阻止修改，修改目标段落后会清除旧检查标记。正文中间/非空范围/跨段落/不完整书签、修订和批注范围仍不支持，并返回具体原因。整段新文字继承首个文字片段的格式，不保证混合文字样式及分页完全不变。整篇、多段请求或无法定位时，模型应说明不能执行；这是提示词约束，不能当作模型理解必然正确的保证，仍应检查下载结果。

## 配置

项目根目录 `.env.example` 是模板；首次复制为 `.env`，已有 `.env` 则只补充以下字段：

```dotenv
DEEPSEEK_API_KEY=在此填写新创建的真实密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

不要把密钥发送到聊天、写入源码或使用 `VITE_` 前缀。`.env` 已被 Git 忽略。曾公开的 Key 应在平台撤销并换新。

安装 `backend/requirements.txt` 后正常启动后端即可：应用从项目根目录加载 `.env`，已有进程环境变量优先。修改配置后重启后端。Docker Compose 显式传入上述三个变量，无需把 `.env` 复制进镜像。更改配置后用 `docker compose up -d` 更新容器。

接口遵循 [DeepSeek 官方文档](https://api-docs.deepseek.com/)，使用非流式 Chat Completions 和 JSON 输出。模型名可替换。真实调用需要可用额度；自动化测试使用模拟服务，不消费额度。

## 数据流与接口

1. `POST /api/tasks`，请求 `{ "file_id": "...", "prompt": "润色第一段正文" }`，返回 202 和任务状态。
2. `GET /api/tasks/{id}` 返回状态、阶段、步骤列表、起止时间（Unix 秒）、已用秒数、失败原因及结果。前端每秒查询，网络错误不等于任务失败。
3. `POST /api/tasks/{id}/cancel` 请求停止，返回当前状态；重复停止终态任务不改变结果。

提示词 1–2,000 字符，空白内容不接受。序列化正文上下文最多 40,000 字符，不截断。模型调用总时限 45 秒，不自动重试。模型输出严格限定为单段替换或无法执行。后端校验段落归属、可编辑性、文件指纹、原文、新文字及输出文件大小。API Key、正文、提示词不写入日志。

任务结果保存了修改前后文字和模型的说明。确定性的摘要只陈述实际替换的位置；模型说明不是独立核验结论。任务记录含正文片段和提示词，位于本地 SQLite，应与文件一起备份。

## 状态与取消

`queued → running → completed / failed`；停止路径为 `cancelling → cancelled`。

阶段依次是读取文档、生成修改内容、校验修改、生成文件。这里只显示真实程序步骤，不展示模型内部推理，不模拟百分比。

当前是单用户、单进程实现，全局只允许一个活动任务。不要启动多个 Uvicorn workers 或多个后端副本。SQLite 持久化任务记录，进程内异步执行；服务重启将未结束任务标为失败，不自动再次调用模型。页面刷新通过本地保存的文件 ID 恢复历史与活动任务，停止仍可操作；兼容上一版保存的任务 ID。

取消模型调用仅停止本地等待，不保证供应商立即停止计算或计费。读写文档在线程中执行，取消会等待当前阶段到达检查点，然后清理临时文件。最终发布与取消检查在同一事件循环串行执行；文件元信息与完成状态在同一 SQLite 事务保存，发布失败清理输出。成功发布后收到停止请求仍返回已完成。

数据库与文件系统不能形成跨系统事务：突然断电可能留下未登记文件。普通失败和协作取消会清理临时文件，启动时也会清理本功能的 `task-*.tmp`；不要在执行期间手动修改数据目录。

## 文件历史与对话布局

- 无文件或文件没有任务记录：显示首页，已选择文件时保留文件标签。
- 文件有记录，或首次任务创建成功：进入连续对话。成功、失败、停止及执行中的任务均为记录。创建请求失败保留首页和草稿。
- 用户提示词显示在右侧，执行过程和结果显示在左侧。输入框固定底部，历史区域独立滚动，支持加载更早记录；查看旧记录时不强制滚动。
- 成功自动选中修改版，失败或停止保留当前输入版本。输入框清空后可直接输入下一轮要求。每轮只将本轮要求和当前文档传给模型，这不等于模型具有对话记忆。
- 文件标签 × 清除选择、草稿和当前页面，返回首页；不删除服务端历史。文件管理中的真正删除会删除整个项目（源文件、全部修改版与对话历史）。
- 查询历史期间显示加载状态；失败可以重试，不能将失败当作“无历史”并发送任务。

`GET /api/files/{id}/history?limit=20&before=<task_id>` 返回：

- `history_id`：稳定版本链 ID。
- `items`：本页记录，按时间从旧到新；首次取最近一页。
- `total`、`next_cursor`：总记录数和更早一页游标，游标为空表示没有更多。
- `current_file`：最近生成且文件仍存在的版本；执行中则使用任务输入文件；无可用版本时为 null。
- `active_task`：同一历史的活动任务，无则为 null。

结果中的文件快照包含 `available`，由当前元信息与磁盘文件判断；删除的文件仍保留名称及修改记录，但不显示下载/预览入口。已删除文件 ID 只要保留历史关联，仍可查询历史。

`file_history(file_id, history_id)` 独立保存关联，不随文件删除。启动时使用现有文件的 `source_file_id` 和旧任务的输入/结果快照恢复版本链；无法追溯的文件单独归组。新版本的关联与文件记录一起提交。迁移可重复执行，不删除已有文件、任务或正文。部署前按既有流程备份数据库和 uploads。

文件删除在 SQLite 写事务中检查活动任务并返回 409；任务创建也在写事务中检查文件并登记任务，避免删除和创建竞争。当前仍是单进程、全局单任务方案。

## 项目入口

右侧改为查询 GET /api/projects，按稳定 history_id 展示原始上传入口。projects 保存源文件 ID、名称、大小与上传时间，修改版不会增加项目数量。同名上传各自建立项目。源文件缺失时保留入口，禁用源文件预览与下载，修改仍恢复可用版本和历史。

DELETE /api/projects/{id} 在写事务内检查活动任务，将文件移至 .project-trash 并写入恢复清单，再删除该项目的任务、文件、关联和项目记录。失败恢复暂存文件；提交后清理。启动时依据项目记录是否存在恢复或清理残留。旧的单文件接口仍用于具体版本，不能代表整个项目删除。
