# Office Agent

通过实际项目学习 Agent 开发：Vue 3 + TypeScript 提供交互，Python + FastAPI 提供文档与模型工具。

## 功能总览

OfficeAgent 是一个单用户、单进程的本地 Word 助手：左侧项目列表，中间对话，右侧项目文件。除文件读写外，所有处理都走同一条受预算约束的工具循环——模型只提出调用，读什么、改什么、能不能发布由后端校验后执行。项目里没有文档时，对话就是普通聊天。

**项目与会话**

- 不上传文件也能聊天，首次发送自动创建项目；标题取首条提示词前 20 个字符，手动重命名后不再被覆盖。
- 项目可重命名、删除；文件、消息与生成版本持久保存，刷新或重启后继续。
- 长会话压缩后仍保留最近六条原话、项目摘要与已确认偏好。

**文档读取与问答**

- 同一项目的多份 `.docx` 可综合问答、总结和追问；`answer_documents` 负责整篇问答，`read_document` 按 `chunk` 定位局部内容。
- 回答用普通文字说明结论与限制；引用保留逐字原文和定位，不展示“原文依据”“阅读范围”栏目。
- 上传时校验 ZIP 结构、正文内容类型与宏标记，单份上限 **10 MiB**，同名文件互不覆盖。

**文档新建与修改**

- 无需上传空白附件即可新建 Word 文档，可引用本轮附件与图片。
- 支持正文和常规表格增删改；生成后按实际结果检查，遗漏最多自动补改两轮。
- 多文件修改在一轮内全部生成、校验后整体提交；任一失败或取消都不发布部分结果，原文件始终保留。
- 修改版按 `_修改版1`、`_修改版2` 递增；明确要求改文件名时生成新名称版本，内容不改也能单独完成重命名。

**本地文件**

- 在聊天里给路径（默认仅当前用户主目录，支持 `~/`）即可统计目录、导入 `.docx`（每轮最多 20 个）、生成修改版。
- 覆盖源文件必须在结果中点击确认；写前生成 `.bak-<时间戳>` 备份，并校验原文件仍是导入时那一份，被其他程序改过则拒绝。

**联网与图片**

- “联网”默认开启，模型按需搜索或读取网页（每轮最多 3 次搜索、5 次读取）；来源可点击并随会话保存，关闭后不调用。
- 可上传图片让模型分析，也可把图片插入现有文档，或作为新文档的图片区块。

**界面交互**

- `@` 唤起项目文件选择（筛选、多选、上下键/Tab/Enter），插入高亮 `@文件名` 并同步为本轮附件；也支持拖拽和按钮上传。
- 处理中显示紧凑的阶段进度与实时活动，结束后可展开查看工具时间线。
- 聊天区右侧锚点条每轮一根短横线，当前轮高亮，点击平滑滚动到该轮。
- 每轮可复制提示词、重新生成、删除整轮，回答可复制；生成结果就地预览、下载、覆盖源文件。

**部署与运维**

- Docker Compose + Nginx，默认只绑定 `127.0.0.1:8080`；数据库与文件挂载在容器外，重建容器不丢数据。
- `scripts/deploy.sh` 支持 `--dry-run` 预检、同步、备份、发布会话与健康检查。
- 旧项目、消息与文件关系在后端启动时幂等迁移；中断的发布残留按 `publication-*.json` 清理。

**能力边界**

- 单用户、单进程、同时只跑一个活动任务；没有账号与权限，不应直接作为多人公网文件服务。
- 单轮工具预算：8 步、40 次模型调用、120 秒；超限会说明原因并停止。
- 服务重启会终止未完成任务，不自动重跑。

## 文档处理与项目会话

可以不上传文件直接聊天，首次发送创建项目并保存会话。上传文件会创建“新项目”，之后追加文件仍属于当前项目。首条提示词去除首尾空白后取前 20 个字符作为标题，超出加省略号；手动重命名后不会被后续消息覆盖。

同一项目支持多份 DOCX，提供综合问答和多文件增删改。普通聊天、总结、问答与澄清正常显示文字；实际文档修改才显示结果文件和逐项改动。处理中显示紧凑的阶段进度条和实时活动，完成后过程可展开查看；回答正文支持基础 Markdown，文件结果使用图标操作，参考来源默认折叠。每份源文件独立记录最新修改结果，原件不覆盖。多文件修改先全部生成、校验，再一次提交；任一失败或取消，整轮不发布修改。

项目里已有附件不代表每轮都要处理它：与文档无关的问题直接回答，不会再要求先确认文件；只有需要读取附件正文或明确修改时才选择文件。模型能看到项目记忆、附件与当前版本信息，长会话压缩后仍保留最近六条原话。

点击左侧项目名称即可恢复消息和附件选择；项目行菜单或输入框工具栏的“项目文件/选择本轮附件”会从右侧打开文件抽屉，勾选本轮附件，每行可用图标下载、预览或删除原件。修改结果在对应消息中单独预览、下载。输入框附件 × 只取消本轮选择，保留草稿、已上传文件和对话；“新会话”才清空当前界面。

每轮对话都有就地操作：提示词下方可复制提示词或删除整轮（二次确认后提示词与回复一起删除，该轮生成的文档保留在项目中）；回答结束后底部可复制回答、用同一提示词重新生成一轮，或删除整轮。聊天区右侧的锚点条每轮一根短横线，当前轮高亮，悬停显示提示词，点击平滑滚动到该轮。

版本恢复已停用（旧恢复接口返回 410），历史生成文件仍可访问。界面不再展示“原文依据”“阅读范围”栏目；读取限制影响回答时通过普通回复说明。

首次配置时将根目录 `.env.example` 复制为 `.env` 并填写 `DEEPSEEK_API_KEY`；已有 `.env` 请补充字段，不覆盖配置。后端读取密钥，前端无需配置。Docker 部署需重新构建前后端。服务重启终止未完成任务，不自动重跑；仍为单用户、单进程、一个活动任务。

后端启动自动幂等迁移旧项目、消息和文件关系。备份应包含整个数据目录。项目删除同时删除全部源文件、生成文件、任务、消息及摘要；运行任务期间禁止删除或追加文件。`.project-trash` 用于项目删除恢复，`publication-*.json` 用于中断后的文件发布清理，不应手动修改。

无需上传空白附件即可请求生成 Word 文档；上传文件后，明确修改才修改，另建文档则创建独立文件。支持参考附件、预览、下载、删除及后续修改。

文档修改会检查临时生成的实际结果，发现遗漏时最多自动补改两轮，完整通过后再保存。补改或停止不会发布部分结果，补改没有产生新修改时立即停止并说明未满足的要求。明确要求改文件名时生成带新名称的版本，内容不改动也可单独完成重命名；没有改名的修改版本按 `_修改版1`、`_修改版2` 递增编号。

## 联网搜索与网页阅读

输入框“联网”默认开启：模型按需调用搜索或网页读取工具，普通闲聊无需搜索。支持北京当天天气、近期资讯以及文章链接总结；关闭后不调用搜索或读取服务。查询过程可停止，回答附可点击来源并与项目一起保存。

后端默认使用 DeepSeek Search / Fetch API 及现有 API Key；每轮最多 3 次搜索、5 次网页读取。

## 本地文件（仅主目录）

在聊天框直接写路径即可，不需要先上传。路径必须由你给出（支持 `~/...`），默认只允许当前用户主目录；可用 `OFFICE_AGENT_LOCAL_ROOTS` 追加目录。只有 `.docx` 会被读取或修改，目录统计只读文件名与扩展名。

问“你能读取我的本地文件吗”这类能力问题时，助手会直接回答可以，并说明需要你给出路径、支持哪些操作和限制。

示例：

- `看下 ~/work 下有几个文件，有多少 .docx，有多少 .py`
- `把 ~/docs 下的 .docx 导入并总结`
- `修改 ~/docs/测试.docx，在最后一行增加一句：这是测试内容`

修改本地文件时**不会直接改原文件**：生成的新版本进入当前项目，结果下方显示"原文件未改动"和「覆盖源文件…」按钮。点击后弹出确认框，确认才写回原路径；写回前自动在同目录生成 `.bak-<UTC时间戳>` 备份，并校验原文件仍是导入时的同一份（被其他程序改过则拒绝）。重复点击、生成文件已删除、关闭开关都会给出明确提示。

开关见 `.env.example`：`OFFICE_AGENT_LOCAL_FS`（统计/导入）与 `OFFICE_AGENT_LOCAL_WRITE`（确认后覆盖），默认开启；服务器或 Docker 部署建议设为 0，因为"本地"此时指服务器文件系统。

## 环境与启动

Node.js 22（本地环境 22.8.0；依赖也兼容 Node 20），Python 3.15（本地 3.15.1）。前端用 npm 与 package-lock.json，后端用独立虚拟环境。

已有项目无需重新克隆。第一次获取：

```bash
git clone https://github.com/Sin-cp/office_agent.git
cd office_agent
```

终端一，从项目根目录启动后端：

```bash
cd backend
python3 -m venv .venv              # 首次创建即可
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Windows PowerShell 使用 `python -m venv .venv` 创建环境，使用 `.venv\Scripts\Activate.ps1` 激活。

终端二，从项目根目录启动前端：

```bash
cd frontend
npm ci
npm run dev
```

- 页面：http://localhost:5174
- API 文档：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/health

Vite 将 `/api` 请求代理到 8000 端口。生产部署需要 Nginx 配置相应代理。服务停止时在各自终端按 Ctrl+C；如果端口占用，先检查已有服务，不要重复启动或随意停止其他程序。

升级后如果依赖有变化，重新执行 `python -m pip install -r requirements.txt`；后端需重启以执行数据库迁移与发布残留清理。

## 文件与数据库

```text
backend/data/
├── office_agent.db       SQLite 元信息：项目、文件、版本、任务与消息
└── uploads/
    └── <storage-key>     原文件、生成版本与图片资产，按存储键命名
```

目录在后端启动时自动创建，位置相对于代码固定，不受工作目录影响。`OFFICE_AGENT_DATA_DIR` 环境变量可指定其他目录，测试使用临时目录。数据目录全部被 Git 忽略。

数据库不存 Word 内容；本地文件不使用用户文件名作为路径。以后可以把文件存储替换为 OSS，保留文件 ID 和元信息接口。备份时应同时备份数据库和 uploads 目录。

## API

接口统一挂在 `/api` 下，完整定义见 `/docs`。

| 接口 | 作用 |
| --- | --- |
| `POST /api/projects` | 新建空项目（默认名“新项目”，首条提示词后自动命名），成功 201 |
| `GET /api/projects?limit=20&offset=0` | 倒序列出项目，附带文件数与源文件是否可用 |
| `PATCH /api/projects/{id}` / `DELETE /api/projects/{id}` | 重命名项目；删除项目及其文件、消息与版本 |
| `GET /api/projects/{id}/files` / `GET /api/projects/{id}/history` | 项目源文件与历史消息 |
| `POST /api/files` | multipart 字段 `file` 上传 `.docx`，成功 201 |
| `GET /api/files?project_id=&limit=20&offset=0` | 按项目倒序列表，返回 `items` 和 `total` |
| `GET /api/files/{id}/download` / `DELETE /api/files/{id}` | 下载原文件；删除单份项目文件 |
| `GET /api/files/{id}/content` / `GET /api/files/{id}/history` | 读取文档块结构；文件的版本历史 |
| `POST /api/tasks` | 提交一轮请求（提示词、项目、附件、图片、是否联网），成功 202 |
| `GET /api/tasks/{id}` / `POST /api/tasks/{id}/cancel` | 轮询任务状态、阶段与结果；取消进行中的任务 |
| `DELETE /api/tasks/{id}` | 删除单轮任务记录 |
| `POST /api/tasks/{id}/overwrite-local` | 用户确认后，用该轮生成的版本覆盖本地源文件（保留 `.bak` 备份） |
| `POST /api/projects/{id}/images` / `GET /api/images/{id}/download` | 上传图片资产；下载图片 |
| `GET /api/health` | 进程健康检查，版本 0.4.0 |

文件对象字段：`id`、`name`、`size`（字节）、`created_at`（UTC ISO 时间）；内部 storage_key 不暴露。

无效文件返回 400，超限返回 413，文件不存在或磁盘文件丢失返回 404，保存失败返回 500。当前大小校验在应用读取上传临时文件时执行；公网部署还需网关请求大小限制和用户权限。

## 前端组件

标准交互组件使用 Element Plus：可折叠项目侧栏、项目文件抽屉、预览对话框、输入框、开关、按钮、下拉菜单、提示、空态和骨架屏。左侧面板参考 DSH 客户端的布局：顶部为 OfficeAgent v1.0.0 与「新会话」，下方为项目列表；收起后通过左上角按钮重新展开。聊天布局、拖拽/输入法处理、Word 预览和会话状态机保留自研。

## Docker 与 ECS 部署

新增 Docker 多阶段构建、Nginx 反向代理和 Compose 配置。默认只绑定 `127.0.0.1:8080`，ECS 个人测试通过 SSH 隧道访问；数据库和文件挂载在容器外，避免重建丢失。容器默认运行工具循环，不需要额外开关。

本地 Docker 开发启动方式和原来的 Vite/FastAPI 开发方式可以分别使用，端口互不相同。

## 一键同步并部署

本地已配置到服务器的 SSH 密钥或别名后，在项目根目录执行：

```bash
./scripts/deploy.sh --dry-run  # 只读预检与同步预览
./scripts/deploy.sh            # 同步、构建、备份、更新及健康检查
```

默认目标为 `root@60.205.124.226:/srv/office-agent/app`。可用 `--host` 指定 SSH 别名、`--remote-dir` 指定项目目录、`--backup-dir` 指定备份目录。同步包含本地未提交的源码，不上传本地 `.env`、数据库或上传文件。发布会短暂停机；当前有文档任务运行或数据目录权限不足时会停止。

脚本实现和本地测试不等于已经发布到线上。
